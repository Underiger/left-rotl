## 指令概要

| 項目 | 內容 |
|---|---|
| 指令名稱 | `ROTL`（組合語言寫作 `rotl rd, rs1, rs2`） |
| 題目類別 | 密碼學／雜湊類 |
| 運算元類型 | 二元 |
| 輸入定義 | rs2 低 5 位元為移位量 n；高 27 位元不問 |
| 語意公式 | `rd = (rs1 << n) \| (rs1 >> (32 − n))`，n = 0 時 rd = rs1 |
| 指令格式 | R-type，custom-0（`0001011`）。funct3、funct7 **待教師分配**，現為暫定值，見 [`spec/rotl_isa.h`](spec/rotl_isa.h) |

```
rotl rd, rs1, rs2      n = rs2 & 31;  rd = n == 0 ? rs1 : (rs1 << n) | (rs1 >> (32 − n))
```

註：本書所稱「左」，係指位元編號遞增方向，與路線無關。

## 實施辦法

需要：`cc`（主機 C 編譯器）、`python3`（3.10 以上）、`riscv64-elf-gcc`。以下指令在本倉庫根目錄執行。

```bash
make test      # 全面檢查：C 測試 + UBSan + 22 項 Python 測試（含模擬器）
make counts    # 重新量測指令數，寫入 report/figures/
make encode    # 印出 rotl 的機器碼範例
make asm       # 產生編譯器輸出的組合語言 build/rotl_O0.s、build/rotl_O2.s
make ub-demo   # 反例：未處理 n = 0 的寫法（預期報錯）
make verify    # 效能驗證（ARM64 實機量測只在 ARM64 電腦上執行，結果只作旁證）
```

`tools/rv32sim.py` 是模組，沒有主程式，單獨執行不會跑任何測試，結束碼照樣是零。請用 `make test`。

## 執行結果

截至 CP3：

一、C 參考實作：16 組測資、69,000 次交叉比對、2,000 組 × 3 項性質檢查、UBSan，全部通過。

二、RV32IM：手寫無分支版 4 條指令（不含 `ret`），GCC `-O2` 為 5 條，自訂指令 1 條。逐字翻譯版（含分支）保留為對照。

三、動態指令數（模擬器實測，GCC 16.2.0 `-O2`）：

| 核心 | RV32IM | ROTL | IC 比 |
|---|---:|---:|---:|
| ChaCha20 區塊 | 1919 | 1284 | 1.49x |
| RC5 金鑰排程 | 2467 | 2000 | 1.23x |
| RC5 加密一個區塊 | 227 | 131 | 1.73x |

四、效能驗證（[`experiments/`](experiments/README.md)，不屬於 CP3 繳交內容）：IC 以反組譯手算交叉驗證，一致；5 級 pipeline 模型的 cycle 比 1.21x–1.67x；ARM64 實機以 `ror` 量得 1.29x–1.52x，只作旁證。前提是 ROTL 不拉長 clock period，待 CP4 確認。

## 語意規格

### ROTL

- **語意（公式）**：
  - `n = rs2[4:0]`（即 `rs2 & 31`）
  - 若 `n = 0`，`rd = rs1`
  - 否則 `rd = (rs1 << n) | (rs1 >> (32 − n))`，其中 `>>` 為**邏輯右移**，結果取低 32 位元
  - 等價的位元定義：`rd[i] = rs1[(i − n) mod 32]`，`i = 0 … 31`
- **運算元與定義域**：
  - `rs1`：任意 32-bit 位元向量，不區分有號或無號
  - `rs2`：任意 32-bit 值，**只使用低 5 位元**，高 27 位元不問。因此 `rs2 = 32` 等同 `n = 0`，`rs2 = −1`（`0xFFFFFFFF`）等同 `n = 31`
- **結果範圍**：任意 32-bit 值。旋轉不遺失位元，`rd` 中 1 的個數與 `rs1` 相同
- **邊界條件與溢位處理**：
  - `n = 0`：直接回傳 `rs1`。若照公式計算，會出現 `rs1 >> 32`，在 C 語言中是未定義行為，必須單獨處理
  - 不會溢位：移出的位元從另一端繞回
  - `n = 31`：左旋 31 位，等於右旋 1 位（T04）。左旋到頭，就是右旋
  - `rd = x0`：結果丟棄（與其他 R-type 指令相同）
  - `rd` 與 `rs1` 或 `rs2` 為同一暫存器：先讀取來源，再寫回 `rd`
- **測試向量**（完整 16 組見 [`tests/rotl_vectors.csv`](../tests/rotl_vectors.csv)）：

  | rs1 | rs2 | rd | 說明 |
  |---|---|---|---|
  | `0x80000001` | `1` | `0x00000003` | 一般：最高位繞回最低位 |
  | `0x000000FF` | `8` | `0x0000FF00` | 一般 |
  | `0x12345678` | `0` | `0x12345678` | **邊界**：`n = 0` |
  | `0x12345678` | `32` | `0x12345678` | **邊界**：`rs2 ≥ 32` 只取低 5 位元 |
  | `0x12345678` | `31` | `0x091A2B3C` | **邊界**：最大移位量，等於右旋 1 位 |

- **對應的 RV32IM baseline 片段與指令數**：

  ```asm
  # a0 = rs1, a1 = rs2，結果放 a0（無分支版，4 條）
  sll   t0, a0, a1      # rs1 << (rs2 & 31)
  neg   t1, a1          # (−rs2) 的低 5 位元 = (32 − n) & 31
  srl   t1, a0, t1      # n = 0 時移 0 位
  or    a0, t0, t1      # n = 0 時 rs1 | rs1 = rs1
  ```

  | 寫法 | 每次旋轉的指令數 |
  |---|---:|
  | 手寫無分支版（上方） | 4 |
  | 手寫逐字翻譯版（含 `n = 0` 分支） | 7（`n = 0` 時 2） |
  | GCC 16.2 `-O2` 編譯 C 參考實作 | 5 |
  | 旋轉量為常數時（`slli`、`srli`、`or`／`add`） | 3 |
  | 自訂指令 `rotl` | 1 |

  上表不含函式呼叫的 `call`／`ret`。量測方法與完整數據見 [`report/CP2.md`](../report/CP2.md)、[`report/CP3.md`](../report/CP3.md)。

- **實際效能**：指令數變少，不一定代表變快。本組另以三種方法驗證，結果放在 [`experiments/`](../experiments/README.md)，不屬於 CP3 的繳交內容：

  | 驗證 | 結果 |
  |---|---|
  | 動態指令數（以反組譯手算，與模擬器交叉驗證） | IC 比 1.23x–1.73x |
  | 5 級 pipeline 的 cycle 數（模型估計） | 1.21x–1.67x |
  | 真實 CPU 上的旋轉指令（ARM `ror`，Apple M5 實測，旁證） | 1.29x–1.52x |

  前提是 ROTL 不拉長 clock period，待 CP4 畫出 datapath 後確認。

## 編碼

```
31      25 24   20 19   15 14  12 11    7 6       0
+----------+-------+-------+------+-------+---------+
|  funct7  |  rs2  |  rs1  |funct3|  rd   | 0001011 |
+----------+-------+-------+------+-------+---------+
  0001111*                   000*
```

\* `funct3`、`funct7` 由教師分配，上面是**暫定值**：funct7 取題號十五（`0001111`），funct3 取 `000`。分配下來以後，只需修改 [`spec/rotl_isa.h`](rotl_isa.h) 的兩個 `#define`，再執行 `make test counts encode`。

## `rotl_isa.h`

[`rotl_isa.h`](rotl_isa.h) 是 ROTL 編碼的**唯一設定來源**。暫定的東西，要有一個地方管；管的地方，只能有一個：

- `ROTL_OPCODE`、`ROTL_FUNCT3`、`ROTL_FUNCT7`
- 組合語言巨集 `rotl rd, rs1, rs2`（展開為 `.insn r`）
- C 函式 `rotl_insn(rs1, rs2)`（以 inline assembly 發出一條 `rotl`）

C、組合語言與 `tools/rotl_isa.py` 都從這個檔案讀取 funct3、funct7。

本組的 `rotl` 不是 Zbb 指令。報告與程式中一律使用 `rotl` 這個名稱，避免混淆（對照見 [`report/CP3.md`](../report/CP3.md) 第 2.6 節）。

參考資料見 [`references/README.md`](../references/README.md)。
